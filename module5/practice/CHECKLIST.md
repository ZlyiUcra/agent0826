# Чекліст картки — статус і докази

Чекбокси відтворені дослівно з картки курсу, у тому ж порядку і тим самим формулюванням, щоб можна було
звіряти поруч із дошкою. Під кожним — доказ: команда, вивід або розділ README.

Легенда: `[x]` — зроблено і доведено, `[ ]` — не зроблено, з причиною поруч.

Стан на 2026-08-29 — **9 з 9**. Шість пунктів закриті командами, які може повторити будь-хто з цієї теки;
три — ручними прогонами власника в Inspector і Claude Code, і під кожним із них записано, що саме він
побачив.

У картці один чекліст, «Основа»; необов'язкової частини, як у модулях 2 і 4, тут немає.

Усі команди виконуються з теки `module5/` інтерпретатором `.venv/bin/python`. Жодна з них не звертається до
Anthropic, тому всі безкоштовні; у мережу з них не ходить теж жодна, а Qdrant, коли він увімкнений, відповідає
на `localhost`. Що саме шукати у виводі — під кожним пунктом; дослівні прогони — у `README.md` і в `out/`.

### [x] Обрав своє API — те, з яким справді працюю

Своє API — шар пошуку по специфікації ECMAScript, зроблений у практиці модуля 2 і використаний далі в
практиках модулів 3 і 4: розділи специфікації у теках `docs*/`, поділені на фрагменти, та індекс BM25 над
ними. Це не обгортка, написана під завдання: той самий код возять агенти трьох модулів курсу. Типово сервер
бере найширший набір — усю ECMA-262 разом з ECMA-402, ECMA-404, ECMA-414 і вільними документами, на які
спирається 402: 4171 фрагмент із 71 документа. Вужчі набори `full` і `core` вмикаються змінною
`PRACTICE_DOCS` (README, розділ «Які розділи тут лежать»).

Доказ, що це справді той самий код, а не схожий:

```bash
diff ../module4/practice/common/corpus.py  practice/common/corpus.py    # мовчить
diff ../module4/practice/common/lexical.py practice/common/lexical.py   # мовчить
diff -r ../module4/practice/docs practice/docs                          # мовчить
diff -r ../module4/practice/docs-full practice/docs-full                # мовчить
diff -r ../module4/practice/docs-suite practice/docs-suite              # мовчить
```

`common/__init__.py` — єдиний із перенесених файлів, що відрізняється, і тільки докстрінгом. Решта того, що
лежить у `common/`, з модуля 4 не бралася: пошук за змістом тут написаний наново, бо в модулі 4 його рахує
torch і тримає в пам'яті процесу, а серверу по stdio потрібні швидкий старт і сховище, яке переживає
перезапуск (README, розділ «Два способи шукати»).

### [x] Сервер запускається і не падає

```bash
timeout 10 .venv/bin/python practice/base/spec_mcp.py; echo "код виходу: $?"
```

Друкує `spec_mcp: набір «suite», проіндексовано 4171 фрагмент з 71 розділу` і код виходу `124`. Саме `124`
тут і є доказом: цей код ставить `timeout`, коли знімає процес, який ще працював. Якби сервер упав, код був би
інший, а на екрані був би стектрейс. Сервер по stdio й має мовчки чекати клієнта — це не зависання.

Виконувати це треба в живому терміналі. Якщо запустити ту саму команду там, де stdin закритий — зі скрипта,
з `< /dev/null`, з чужого харнеса, — сервер побачить кінець вводу одразу, коректно завершиться сам, і код
виходу буде `0`. Це теж не падіння, але доказом уже не є: `timeout` нікого не знімав.

Що він не падає під навантаженням протоколу, показують два наступні пункти: `check.py` і `raw.py` ведуть із
ним повний діалог і завершуються нулем.

### [x] Описи переписані так, щоб з них було зрозуміло КОЛИ викликати, а не лише що робить

Повний текст обох описів — README, розділ «Описи інструментів», разом із розбором, навіщо там кожен абзац.
Коротко: кожен опис відповідає на чотири питання — що робить, коли кликати, коли **не** кликати, звідки
беруться аргументи. Для порівняння, курсовий `courier_server.py`, з якого картка радить починати, описує
свій інструмент одним рядком: `"""Статус посилки за штрихкодом."""`.

Найдорожча правка знайдена перевіркою, а не написана з голови: токенізатор індексу — це `[a-z0-9_]+`, тому
будь-який суто український запит дає нуль токенів і `found: 0`. Опис `search_spec` тепер прямо каже моделі
писати запит англійською і відповідати мовою користувача.

```bash
.venv/bin/python -m practice.base.smoke | grep -E "опис|кирилиц|українськ"
```

Дванадцять рядків `ok`: кирилиця дає нуль токенів; суто український запит повертає `found=0`; український
запит із латинським ідентифікатором працює; опис `search_spec` попереджає про мову запиту, каже, як писати
українську відповідь, і пояснює поле `search`; приклад ідентифікатора в описі `read_section` справді існує;
обидва описи довші за один рядок і обидва містять «коли НЕ викликати»; речення про завантажений набір
доїхало до опису.

Перевірка про приклад ідентифікатора з'явилася не наперед, а після того, як знайшла помилку: в описі
`read_section` стояв приклад `14-object-objects#20.1.3.6/2`, правильний для набору `core` і неіснуючий для
`full` та `suite`. Модель копіює приклад дослівно, тож такий рядок навчав би її кликати інструмент так, як він
не працює. Тепер приклад бере сам сервер із завантаженого індексу, і перевірка проходить на всіх трьох
наборах.

Те, що описи доїжджають до клієнта саме такими, видно в тілі відповіді `tools/list` — обидва абзаци «коли не
викликати» приїжджають одним кадром, тому рахувати треба входження, а не рядки:

```bash
.venv/bin/python -m practice.base.raw --full | grep -o "Do not" | wc -l    # 2
```

### [x] Ключі в .env, .env у .gitignore

Серверу ключі не потрібні взагалі: до Anthropic він не звертається жодного разу, а з мережею говорить лише
на `localhost` — це Qdrant, і лише тоді, коли пошук за змістом увімкнули. Один раз у мережу виходить
підготовка: `fastembed` довантажує модель на 128 МБ із Hugging Face і кладе її в `~/.cache/huggingface`. Ключа
не просить ані те, ані те. Тому пункт закривається двома фактами, а не наявністю ключа в коді.

`.env` модуля лежить у `.gitignore` і git його не бачить:

```bash
cd .. && git check-ignore -v module5/.env      # module5/.gitignore:1:.env	module5/.env
```

У коді практики немає ані ключа, ані звернення до нього, ані клієнта служби, яка ключа потребує:

```bash
grep -rn "sk-ant\|api_key\|ANTHROPIC\|dotenv" practice/base practice/common   # порожньо, код виходу 1
grep -rn "anthropic\|httpx\|openai" practice/base practice/common             # порожньо, код виходу 1
```

Стороння бібліотека тут одна — сам MCP SDK; у `spec_mcp.py` і `check.py` він імпортується під `try`, бо в
SDK 1.x клас звався `FastMCP`, а в 2.x — `MCPServer`. Решта імпортів — стандартна бібліотека, рівно п'ять:

```bash
grep -h "^import \|^from " practice/base/*.py | grep -v practice | sort -u
# asyncio, json, pathlib, subprocess, sys
```

Єдина змінна оточення, яку читає цей код, — `PRACTICE_DOCS` у перенесеному `common/corpus.py`; вона обирає
набір документів і секретом не є. Її межі описані в README, розділ «Відомі межі».
