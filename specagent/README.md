# Агент-довідник специфікації ECMAScript

Питання на кшталт «чому `NaN !== NaN`» чи «що робить `Array.prototype.at` із від'ємним індексом» мають точну
відповідь у специфікації ECMA-262, але сама специфікація — сотні сторінок алгоритмічного тексту, і шукати в
ній руками довго. Цей агент бере питання звичайною мовою, сам вирішує, що шукати в тексті специфікацій, за
потреби дочитує знайдені розділи повністю і відповідає стисло — з номером розділу, на який можна послатися в
код-рев'ю чи багрепорті.

Для користувача це одна команда: питання на вході — відповідь із посиланням на розділ на виході. Скільки
кроків пошуку зробити, які розділи дочитати і коли зупинитися — агент вирішує сам, у межах ліміту кроків.

## Швидкий старт

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env                                 # впишіть свій ключ Anthropic

.venv/bin/python -m practice.base.agent --tools      # $0: перевірка з'єднання з сервером знань
.venv/bin/python -m practice.base.agent "Чому NaN !== NaN?"   # платний прогін
```

Запускати з кореня цієї теки: код імпортує `config`, `core` і `practice` як пакети верхнього рівня.

### Ланцюжок виконання `NaN !== NaN`

Оператор `!==` є запереченням `===`, а `===` реалізується через абстрактну операцію **`IsStrictlyEqual`** (розділ **7.2.14**):

1. Якщо типи `x` і `y` різні — повернути `false`.
2. Якщо `x` — це Number — повернути **`Number::equal(x, y)`**.

Далі **`Number::equal`** (розділ **6.1.6.1.13**) виконує:

> 1. Якщо `x` is `NaN` — повернути **`false`**.
> 2. Якщо `y` is `NaN` — повернути **`false`**.

Тобто **будь-яке** порівняння, де хоча б один операнд є `NaN`, негайно повертає `false` — навіть якщо обидва операнди `NaN`.

---

### Чому так зроблено?

Це свідоме рішення, що відповідає стандарту **IEEE 754** для чисел з плаваючою комою. `NaN` означає «не число» — результат невизначеної операції (наприклад, `0/0`, `Math.sqrt(-1)`). Два «невизначені результати» логічно не можна вважати рівними один одному.

Зверніть увагу: `SameValue` (розділ **7.2.9**, використовується в `Object.is()`) поводиться **інакше** — там `NaN === NaN` дає `true`, бо `Number::sameValue` (розділ **6.1.6.1.14**) спершу перевіряє `if x is NaN and y is NaN → return true`.

```js
NaN === NaN          // false  (IsStrictlyEqual → Number::equal)
Object.is(NaN, NaN) // true   (SameValue → Number::sameValue)
Number.isNaN(NaN)   // true   (єдиний надійний спосіб перевірити NaN)
```

## Reflect vs Object: навіщо два інтерфейси?

### Ключова ідея Reflect (розділ 28.1)

`Reflect` — це звичайний об'єкт (не функція, не конструктор), чиї методи **один-до-одного відповідають внутрішнім методам (`[[...]]`) об'єктів** і **пасткам Proxy-обробника**. Тобто `Reflect.defineProperty` → `[[DefineOwnProperty]]`, `Reflect.get` → `[[Get]]`, і т. д. `Object` ж — старіший API, який вирішує ширші задачі.

---

### Конкретна різниця: `Reflect.defineProperty` vs `Object.defineProperty`

Специфікація описує обидва в кроках чітко. Перші три кроки **однакові**:

1. Якщо аргумент не Object — кинути `TypeError`.
2. Привести ключ через `ToPropertyKey`.
3. Привести дескриптор через `ToPropertyDescriptor`.

Але четвертий крок — **принципово різний**:

| | `Reflect.defineProperty` (§28.1.3) | `Object.defineProperty` (§20.1.2.4) |
|---|---|---|
| **Що робить** | `Return ? target.[[DefineOwnProperty]](propertyKey, propertyDesc)` | `Perform ? DefinePropertyOrThrow(obj, propertyKey, propertyDesc)` → `Return obj` |
| **При невдачі** | **Повертає `false`** | **Кидає `TypeError`** |
| **При успіху** | **Повертає `true`** | **Повертає сам об'єкт** |

`DefinePropertyOrThrow` (§7.3.8) — це обгортка, яка викликає `[[DefineOwnProperty]]` і, якщо той повернув `false`, кидає `TypeError`. `Reflect.defineProperty` цю обгортку **не використовує** — він повертає `Boolean` напряму.

---

### Три практичні наслідки

1. **Обробка помилок без try/catch.**
   ```js
   // Object — треба try/catch
   try { Object.defineProperty(obj, 'x', { value: 1 }); }
   catch (e) { /* невдача */ }

   // Reflect — просто перевіряєш результат
   if (!Reflect.defineProperty(obj, 'x', { value: 1 })) { /* невдача */ }
   ```

2. **Природна пара для Proxy-пасток.**
   Усередині обробника `defineProperty` пастки треба повернути `Boolean`. `Reflect.defineProperty` повертає саме `Boolean`, тому це єдиний логічний спосіб «прокинути» виклик до цілі:
   ```js
   new Proxy(target, {
     defineProperty(t, key, desc) {
       console.log('intercepted');
       return Reflect.defineProperty(t, key, desc); // Boolean ✓
     }
   });
   ```

3. **Повертає об'єкт vs Boolean.**
   `Object.defineProperty` повертає **сам об'єкт** (для ланцюгових викликів у старому стилі); `Reflect.defineProperty` повертає **`true`/`false`** як сигнал успіху.

---

**Підсумок:** `Reflect` — не дублювання `Object`, а **рефлексивний дзеркальний шар** над внутрішніми методами об'єктів. Головна різниця з `Object.defineProperty` — замість викидання виключення при невдачі **повертається `false`**, що зручно в Proxy-пастках і в коді, де потрібен явний Boolean-результат.

## Порядок ключів у `Object.keys`

`Object.keys` визначено в розділі **20.1.2.22**. Там написано, що функція викликає абстрактну операцію **`EnumerableOwnProperties(obj, key)`** (розділ **7.3.23**), яка своєю чергою отримує список ключів через внутрішній метод **`[[OwnPropertyKeys]]()`** об'єкта.

Порядок, у якому `[[OwnPropertyKeys]]` повертає ключі, визначено в розділі **10.1.11.1 `OrdinaryOwnPropertyKeys`** і є таким (три групи, строго по черзі):

1. **Цілочислові індекси** (array indices) — у **зростаючому числовому порядку** (ascending numeric order).
   Наприклад: `"0"`, `"1"`, `"2"`, …

2. **Рядкові ключі, що не є індексами** — у **хронологічному порядку створення** (ascending chronological order of property creation).
   Наприклад: `"foo"`, `"bar"`, `"baz"`, …

3. **Symbol-ключі** — у хронологічному порядку створення.
   *(але `Object.keys` їх не повертає, бо `EnumerableOwnProperties` пропускає не-рядкові ключі)*

---

### Приклад

```js
const obj = { b: 1, 2: 2, a: 3, 0: 4, 1: 5 };
Object.keys(obj);
// → ["0", "1", "2", "b", "a"]
//      ↑ індекси за зростанням  ↑  рядки в порядку створення
```

---

**Підсумок:** порядок ключів у `Object.keys` — не довільний і не "порядок вставки" у чистому вигляді. Спочатку йдуть числові індекси за зростанням, потім решта рядкових ключів у порядку їхнього додавання до об'єкта. Це гарантується специфікацією через ланцюжок: `Object.keys` → `EnumerableOwnProperties` (§7.3.23) → `[[OwnPropertyKeys]]` → `OrdinaryOwnPropertyKeys` (§10.1.11.1).

## Що всередині

Агент — це цикл ухвалення рішень над моделлю Claude. Текст специфікації в саму модель не вшитий: усе, що вона
знає, — це питання користувача і результати власних пошуків. На кожному кроці вона або викликає інструмент
пошуку, або, зібравши досить контексту, пише відповідь. Знання живуть окремо — у
сервері знань, під'єднаному через MCP по stdio, з двома інструментами: `search_spec` (пошук фрагментів за
запитом) і `read_section` (повний текст розділу за id з видачі пошуку). Навколо циклу стоять чотири шари
захисту: фільтр вхідного запиту, правила перед кожним викликом інструмента, список дозволених інструментів і
фільтр готової відповіді з перевіркою окремою дешевою моделлю.

- `practice/base/agent.py` — агент: цикл, виклики моделі, диспетчер інструментів;
- `practice/base/spec_server.py` — сервер знань: індекс специфікацій і два інструменти через MCP;
- `practice/base/layers.py` — чотири шари захисту навколо агента;
- `practice/base/setup.py` — підготовка пошуку (за бажанням — вектори, див. нижче);
- `practice/common/` — корпус, пошук по словах, режим пошуку;
- `practice/docs-full/`, `practice/docs-suite/` — тексти ECMA-262, ECMA-402, ECMA-404 і ECMA-414: 72 файли,
  з яких сервер знань індексує 4168 фрагментів із 71 розділу;
- `config.py`, `core/agent.py` — ключ і моделі з `.env`, клієнт API з ретраями та обліком токенів.

## Пошук: по словах чи за змістом

За замовчуванням сервер знань шукає по словах (BM25) — це не потребує жодних додаткових пакетів і сервісів.
За бажанням пошук перемикається на вектори: `python -m practice.base.setup --vectors` піднімає Qdrant у
Docker, рахує вектори фрагментів (пакет `fastembed`) і перемикає режим; `--words` повертає назад. Для
демонстрації агента вистачає пошуку по словах.

## Вартість і ключ

Платний лише повний прогін: цикл агента працює на `claude-sonnet-4-6`, перевірка відповіді — на дешевій
`claude-haiku-4-5`. Наприкінці кожного прогону агент друкує рядок вартості: скільки коштували виклики моделей
і скільки токенів пішло на вхід і вихід; ціни за мільйон токенів лежать у `core/cost.py`. Рукостискання
`--tools`, підготовка і пошук по словах безкоштовні. Ключ живе тільки у `.env`, який не потрапляє в git.
