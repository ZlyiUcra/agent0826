# Практика модуля 7: спостереження і вимір агента специфікації

Агент нашої лінії практик — той, що відповідає на питання про специфікацію ECMAScript, — цього разу нічого
нового не вміє. Змінилося те, що навколо нього: кожен його крок видно в трейсі з токенами, вартістю і
затримкою, його відповіді міряються набором із двадцяти кейсів, а результат набору проходить через гейт із
порогом. Наприкінці той самий агент, не змінений ані рядком, провалює гейт — бо йому підмінили дані, які він
читає.

Сам агент живе не в цьому репозиторії, а у фабриці `docfactory/` поруч: примірник `instances/ecmascript`,
захищений MCP-сервер з двома інструментами `search_spec` і `read_section`, чотири шари захисту з модуля 6,
пошук по словах разом із пошуком за змістом (BM25 плюс fastembed і Qdrant), корпус із 72 файлів і 4168
фрагментів. Практика підключається до нього через `bootstrap.py`. У самій фабриці змінено три речі, і всі
три названі нижче: виправлено дефект шару 2, дописано перевірку, яка його ловить, і додано синхронний
прогрів векторів, без якого два прогони не можна порівняти.

## Що тут своє, а що зразок

Курсові `otel_tracing.py`, `test_eval_gate.py`, `degradation_demo.py`, `eval_history.py` — зразок. Практика
бере з них рівно одне: перелік адресатів трейсів (`otel_tracing._exporter` знає п'ять — консоль, Phoenix,
Langfuse, LangSmith, довільний OTLP), і другого списку адрес не заводить. Решта написана тут, бо міряється
інший агент.

Три розходження зі зразком названі прямо, щоб їх не читали як помилку:

- Поріг гейта. У курсовому `modules/m07_evaluation.py:43` він `THRESHOLD = 0.2`; тут — `0.80` для скора і
  `0.90` для вибору інструмента (`evaluation.py:34-35`). На нашій деградації курсовий поріг не почервонів
  би: 0.75 більше за 0.2.
- Назва сервісу в трейсах. У курсовому `otel_tracing.py:45` — `agentpro-support-agent`; тут
  `docfactory-ecmascript` (`tracing.py:31`), інакше в приймачі два різні агенти злилися б в один.
- Ціна безкоштовної половини. Курсовий `test_eval_gate.py` бере відповіді з фікстури, яка щоразу проганяє
  платний датасет; тут прогін і перевірка розділені файлом, тому `pytest` не звертається до моделі жодного
  разу.

## Спани: три обгортки замість інструментування сервера

Спани ставляться лише в клієнті-агенті, трьома обгортками, які самі не знають про предметну область
(`tracing.py`):

- `invoke_agent docfactory-ecmascript` — корінь звернення, навколо `server.agent.run`. Несе підсумок:
  токени, вартість, кількість викликів інструментів, ідентифікатор трейсу.
- `chat {model}` — навколо `common.llm._call`, по спану на кожне звернення до моделі, з
  `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens`, кешованими токенами окремо і вартістю за
  таблицею `core/cost.py`.
- `execute_tool {name}` — навколо `server.agent._dispatch`, по спану на кожен виконаний інструмент, із
  тривалістю і полем `docfactory.search.mode`: по словах шукав сервер чи ще й за змістом.

Імена й атрибути — за домовленостями OpenTelemetry GenAI. Ключі написані рядковими літералами навмисно:
пакет `opentelemetry-semantic-conventions` 0.65b0 досі везе старі сталі (`gen_ai.system` замість
`gen_ai.provider.name`, `cache_creation` замість `cache_read`), тож імпорт із нього дав би застарілі імена.

Сервер спанів не ставить. Це свідоме рішення: він піднімається підпроцесом на кожне звернення, і передавати
в нього контекст трейсу довелося б через `params._meta`. Для картки це нічого не додає, а коду додає багато.
Дві речі, які насправді потрібні від сервера, — що саме він повернув і скільки це тривало, — видно в
`execute_tool`.

Приймач — Arize Phoenix локально, на `127.0.0.1:6006`. Чому саме він і чого від нього чекати — у
[SETUP.md](SETUP.md).

## Що видно в трейсах: три погані прогони

Розвідувальний прогін із п'яти питань (`base/run_traced.py`, $0.27) дав три випадки, де агент повівся погано.
Усі три знайдені в трейсах, не вигадані.

**Потрібний розділ аж третій.** На питання про `Object.prototype.toString` агент шукав `Object.prototype.toString
tag`, і перші два місця дісталися `15.1.1 Intl.Locale ( tag [ , options ] )` та геттеру
`23.2.3.38 %TypedArray%.prototype [ %Symbol.toStringTag% ]`. Потрібний `20.1.3.6` — лише третій. Слово `tag`
однаково вагоме в назві аргументу локалі й у назві символа.

**Шум на першому місці.** На українське питання про заморожування агент правильно переклав запит на
`SetIntegrityLevel frozen` — і перше місце дісталося `13.2.8.4 GetTemplateObject`, розділу ні про що.
Потрібний `7.3.15` став другим.

**Стеля шару 2.** Питання «що робить `Promise.all` з рядком» агент розбирав шістьма викликами інструментів і
на сьомому дістав відмову: `шар 2 (перевищено ліміт викликів інструментів (6) за звернення)`. Корінь трейсу
червоний, `error.type = blocked_by_layer`. Це не помилка коду — це стеля, поставлена в модулі 6, і в трейсі
видно, як агент у неї впирається.

Останній випадок трапляється й у повних прогонах: у деградованому прогоні в стелю впиралися три звернення з
двадцяти, і всі три все одно відповіли правильно. Показово, що в журналі сервера цих відмов немає взагалі:
стелю тримає клієнт, тож сервер про сьомий виклик просто не дізнається.

## Набір: двадцять кейсів

`data/evalset.jsonl`, один рядок — один кейс. Поля: питання, очікуваний інструмент, очікуваний розділ,
документ, у якому цей розділ живе, і критерій успіху для судді.

Звідки взялися кейси:

- сім — `seed`: питання, що вже жили в перевірках попередніх практик (`smoke`, `quality`);
- п'ять — `trace`: узяті з розвідувального прогону, кожен несе поле `source_trace` з іменем файла трейсу;
- вісім — `manual`: дописані руками, щоб набір накрив і те, чого в трейсах не було, — граматику, оголошення,
  структуровані дані, порядок ключів і питання про те, чого в специфікації немає взагалі.

Очікуваний документ названий у кожному кейсі не для краси: у корпусі 214 номерів розділів повторюються між
документами — `6.2.2` є і в ECMA-262, і в ECMA-402, і в UTS #35. Номер без документа не адресує нічого.

П'ять кейсів чекають `read_section`, решта — `search_spec`. Для агента з двома інструментами «правильний
інструмент» означає саме це: питання про формулювання кроку алгоритму вимагає дочитати розділ, а не
задовольнитися шестисотсимвольним уривком з пошуку.

## Три перевірки на кейс і один гейт

Дві перевірки безкоштовні й детерміновані, третя платна:

- **інструмент** — чи агент справді виконав той інструмент, якого кейс чекає. Рахується за виконаними
  викликами, а не за журналом наміру: `report["trace"]` дописує й ті виклики, які відхилив шар 2, і за ним
  усе завжди «взято»;
- **опора** — чи кожен номер розділу, названий у відповіді, був серед тих, що повернули інструменти в цьому ж
  прогоні. Сусід по дереву законний: показали `20.1.3.6` — згадка `20.1.3` не є вигадкою;
- **суддя** — чи відповідь задовольняє критерій кейса. Дешева модель, `temperature=0`, відповідь агента
  подана як дані, а не як вказівки.

Гейт агрегований, і блокують дві частки на весь набір: скор не нижче `0.80` і точність вибору інструмента не
нижче `0.90`. Покейсових блокерів немає навмисно — на двадцяти кейсах суддя дає розкид, і покейсовий блокер
зупиняв би реліз через шум. Окремі кейси видно в `pytest` як `xfail`: вони не валять прогін, але їхню причину
надруковано.

## Прогін і перевірка розділені файлом

Платний прогін пише все, що потім потрібно, у `practice/out/run-<мітка>.json`: питання, відповідь, виконані
виклики разом із їхньою видачею, токени, вартість, час, ідентифікатор трейсу і вердикт судді. `pytest` читає
цей файл і до моделі не ходить — тому всі 37 перевірок гейта безкоштовні й ідуть на кожен коміт.

Той самий розподіл дав дешеве калібрування судді: `base/rejudge.py` бере збережений прогін і переоцінює лише
суддею, за копійки замість долара за прохід.

Друга залежність, яку довелося зняти, — сама фабрика. Тека `docfactory/` живе поза репозиторієм курсу, тож у
клоні її немає, а дві перевірки набору питали саме її: чи дозволений агентові інструмент, якого чекає кейс, і
чи існує очікуваний розділ у названому документі. Тепер обидві читають `data/corpus-passport.json` — знімок,
який `base/passport.py` знімає з живого корпусу й кладе під git: перелік дозволених інструментів і, на кожен
очікуваний номер розділу, повний список документів, де цей номер трапляється. Паспорт не замінює корпус, а
датує його, тому поруч стоїть окрема перевірка, яка звіряє паспорт із живим корпусом і падає, щойно вони
розійдуться; без фабрики вона пропускається.

Що з цього виходить на практиці: у голому клоні `python -m pytest practice` дає 13 пройдених перевірок за
0,04 секунди й 24 пропущені з поясненням, чого бракує. З фабрикою поруч — 37 перевірок, з них одна звіряє
паспорт, а решта читає останній збережений прогін.

## Точка відліку

`base/run_eval.py --label baseline`: **17/20 = 0.85, гейт PASS**, точність вибору інструмента 1.0, агент
$0.977, суддя $0.035.

Дорога до цього числа коштувала двох платних прогонів і трьох пересудів, і кожен знайшов дефект у вимірі, а
не в агентові. Перший прогін дав 11/20, і сім із дев'яти провалів були дефектами перевірок, а не
відповідей:

- `3.14` у прикладі коду читалося як номер розділу — тепер код і рядкові літерали вирізаються перед пошуком
  номерів;
- однорівневий номер («12 Lexical Grammar») загальний вираз не брав узагалі;
- номер у кінці речення («…у 20.1.3.6.») не розпізнавався через крапку — а це найчастіше місце для номера;
- критерії вимагали номер розділу вдруге, після детермінованої перевірки, і суддя валив відповіді, які
  пояснювали правильну річ, але називали сусідній розділ. Тепер номер — справа детермінованої перевірки,
  суддя оцінює лише зміст;
- суддя бачив два уривки по 400 символів і на такій довідці заявив, що `IsLooselyEqual` не доходить до
  `ToNumber`. Тепер бачить до шести уривків по 900 символів;
- вартість судді рахувалася від поверхневої копії лічильників і завжди виходила нулем.

До першого прогону знайшовся й дефект у самій фабриці: `server/layers.py` читав ключ `hits`, тоді як сервер
повертає `passages`, тож набір показаних агентові фрагментів лишався порожній і шар 2 відхиляв **кожен**
`read_section`. Точка відліку, знята до цього виправлення, описувала б агента, який жодного разу не дочитує
розділ. Виправлено, і стик закритий трьома перевірками в `docfactory/server/smoke.py`.

Третя зміна у фабриці — синхронний прогрів векторів. Сервер прогрівав пошук за змістом у фоні, і це
правильно для роботи: клієнт дістає відповідь одразу, поки що по словах, а за змістом підхоплюється секунд
через десять. Для виміру не годиться: перші питання прогону шукали б по словах, пізніші за змістом, і число
залежало б від того, що встигло раніше. Змінна `DF_VECTORS_WAIT` робить прогрів синхронним, і `bootstrap`
виставляє її завжди.

## Деградація: гейт червоніє

Псувати агента можна промптом, правами або даними. Узято дані — саме тому, що цього не видно.
`base/degrade.py` збирає `docfactory/instances/ecmascript-degraded/`: копію примірника, у якій переписано
дев'ять речень у п'яти розділах чотирьох файлів.

- `20.1.2.6` — `SetIntegrityLevel ( obj , frozen )` стало `SetPropertyLockLevel ( obj , locked )`;
- `20.1.3.6` — теги `[object Undefined]` і `[object Null]` помінялися місцями;
- `21.3.2.29` — рівновіддалене число округлюється до мінус нескінченності; разом із кроком алгоритму і
  прикладом у примітці, інакше текст суперечив би сам собі;
- `12` — текст сканується справа наліво, найкоротшою послідовністю;
- `10.1.11.1` — рядкові ключі поставлено перед цілочисельними індексами, а індекси — за спаданням.

Усе інше тримається однаковим: імена файлів, 4168 фрагментів, їхні ідентифікатори (той самий хеш
`ce71dc62bf5d40a1`), `config.json` байт у байт — отже, та сама колекція Qdrant зі старими векторами. Це і є
звичайний випадок із життя бази знань: документ переписали, а вектори не перерахували. Звірку робить
`degrade.py --check`, безкоштовно.

`base/run_eval.py --instance ecmascript-degraded --label degraded`: **15/20 = 0.75, гейт FAIL**, `pytest`
завершується кодом 1. Точність вибору інструмента лишилася 1.0 — агент бере ті самі інструменти, зіпсовано
лише те, що він у них читає.

Логи при цьому чисті: 65 рядків від прогону в `out/calls.log` деградованого примірника, жодної помилки,
жодного зрізу санітаром. Червоні спани в Phoenix є, але з іншої причини — три звернення вперлися в стелю
шару 2, і всі три відповіли правильно. Тобто ні журнал, ні статуси спанів падіння якості не показують; його
показує тільки набір кейсів.

## Два кейси, які вижили, і чому це важливо

Із шести кейсів, на які цілилася деградація, впали чотири. Обидва кейси про заморожування об'єкта пройшли, і
причина варта окремого абзацу.

Агент прочитав підмінений `20.1.2.6`, побачив невідому йому `SetPropertyLockLevel`, пішов шукати її запитом
`Object.freeze SetPropertyLockLevel locked` — і пошук за змістом віддав йому `7.3.15 SetIntegrityLevel`,
справжню операцію, якої правка не торкнулася. Вектори в колекції описують здоровий текст, тож запит про
вигадану назву привів рівно до тієї операції, яку правка перейменувала в місці виклику, але лишила
недоторканою в місці означення.

Часткова підміна не тримається, коли той самий факт записаний у корпусі ще раз. Для картки це корисніше за
чисті 11/20: гейт червоний, а разом із ним видно, що деградація даних — не одна правка, а робота з усіма
місцями, де факт повторено.

## Чого цей вимір не ловить

- **Розкид між прогонами — близько трьох кейсів із двадцяти.** У деградованому прогоні три кейси, що падали
  на точці відліку, пройшли, а `generator-call`, якого ніхто не чіпав, упав. Саме тому гейт агрегований;
  порівнювати два прогони покейсово не можна.
- **Суддя помиляється приблизно раз на двадцять кейсів.** На точці відліку він відхилив правильну відповідь
  про `IsLooselyEqual`, заявивши, що специфікація не згадує там `IsStrictlyEqual`. Хиткість відтворювана й
  виміряна: ті самі збережені відповіді оцінено чотири рази, детерміновані перевірки збіглися до кейса, а
  `generator-call` перевернувся між двома оцінюваннями однією й тією ж дешевою моделлю на тому самому
  критерії.
- **Перевірка опори бачить розділ у будь-якому десятковому числі.** У відповіді про округлення `0.5` було
  позначено як вигаданий номер розділу. Код і текст у лапках вирізаються, але число в звичайній прозі —
  ні. На вердикт це не вплинуло (кейс і так провалив суддя), проте на числових відповідях перевірка дає
  хибний провал.
- **Гейт міряє двадцять питань, а не агента.** Набір накриває тринадцять документів корпусу з сімдесяти
  двох; поза цими двадцятьма питаннями про якість не сказано нічого.

## Скільки це коштувало

- розвідувальний прогін, п'ять питань — $0.270;
- перша точка відліку, та, що знайшла сім дефектів виміру, — агент $1.034, суддя $0.032;
- точка відліку — агент $0.977, суддя $0.035;
- деградований прогін — агент $1.005, суддя $0.040.

Разом виміряних $3.39. Три пересуди сюди не входять: тоді вартість судді ще рахувалася неправильно, і своєї
цифри вони не лишили — порядок $0.2 за всі три. Прогін двадцяти кейсів триває близько десяти хвилин і робить
69 викликів інструментів.

## Команди

Усі — з теки `module7/`, інтерпретатором примірника (див. [SETUP.md](SETUP.md)):

```
python -m practice.base.run_traced "How does Object.prototype.toString build the tag?"   # платно, одне питання
python -m practice.base.run_eval --label baseline                                        # платно, 20 кейсів
python -m practice.base.rejudge --from baseline --label baseline-v2                      # платно, лише суддя
python -m practice.base.degrade                                                          # безкоштовно
python -m practice.base.degrade --check                                                  # безкоштовно
python -m practice.base.passport                                                         # безкоштовно
python -m practice.base.passport --check                                                 # безкоштовно
python -m practice.base.run_eval --instance ecmascript-degraded --label degraded         # платно, 20 кейсів
python -m pytest practice -q                                                             # безкоштовно, гейт
```

Історія прогонів лежить під git у `data/history.jsonl` — рядок на прогін, зі скором, гейтом, вартістю,
режимом пошуку і моделлю судді. Самі прогони в `out/` git ігнорує: у них лежать повні відповіді.

Ключі — тільки в `.env` примірника фабрики. Кореневий `.gitignore` ігнорує `.env*` і всю теку `docfactory/`;
деградована копія власного `.env` не має навмисно й бере ключ із здорового примірника.
