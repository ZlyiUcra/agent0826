# Установка і розробка

Як підняти оточення практики модуля 4 з нуля і як з ним працювати далі. Усі команди виконуються з теки
`module4/`, не з кореня репозиторію: скрипти імпортують `config`, `core`, `domain` як пакети верхнього рівня.

## Швидкий старт

Три команди, з теки `module4/`, інтерпретатором із `module4/.venv`:

```
.venv/bin/python -m practice.base.system "Як Proxy перехоплює читання властивості?"   # своє питання системі, ~$0.02–0.35
.venv/bin/python -m practice.base.smoke                                                # перевірка дизайну, 41 перевірка, $0
.venv/bin/python -m practice.base.compare                                              # вимір картки: п'ять запитів через обох, ~$1
```

Питання — будь-який текст у лапках, відповідь приходить мовою питання. Повний перелік команд, ціна кожної
і що саме шукати у виводі — у README, розділ «Як перевірити імплементацію».

## Оточення

У модуля власне віртуальне середовище — `module4/.venv`. Глобальним і середовищами сусідніх модулів він не
користується: модуль має підніматися сам по собі, не знаючи про сусідів.

```
cd module4
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install torch --index-url https://download.pytorch.org/whl/cpu
.venv/bin/python -m pip install sentence-transformers python-dotenv
.venv/bin/python -m pip install 'anthropic==0.122.*'
.venv/bin/python -m pip install pypdf
.venv/bin/python -m pip install qdrant-client
```

Чому саме так, а не `pip install -r requirements.txt`:

- Торч ставиться з окремого індексу PyTorch, збірка лише під процесор. Звичайний `pip install torch` тягне
  збірку з CUDA — кілька гігабайтів під відеокарту, якої це середовище не використовує.
- `pypdf` потрібен лише одному скрипту — `challenges/suite_download.py`: два документи набору специфікацій
  ECMAScript, ECMA-404 (JSON) і ECMA-414 (склад набору), Ecma видає тільки як PDF. Без `pypdf` решта
  практики працює як і працювала.
- `qdrant-client` потрібен лише курсовому `knowledge_qdrant.py`, який з'явився з оновленням курсу від
  26 серпня 2026; практика говорить із сервером Qdrant через `urllib` і пакета не імпортує. Поставлено,
  щоб курсовий файл запускався з цього ж оточення: `python knowledge_qdrant.py` (вбудований режим) і
  `QDRANT_URL=http://localhost:6333 python knowledge_qdrant.py` (наш сервер, колекція `postal_rules`,
  чотирнадцять точок) — обидва прогнано 26 серпня 2026.
- Курсовий `requirements.txt` перелічує ще й фреймворковий стек langchain та langgraph, а ragas з
  оновлення курсу від 26 серпня 2026 винесено в `requirements-eval.txt`. Практиці це не потрібне, а
  ставиться довго й важко, тому набір тримається мінімальним. Знадобиться фреймворковий стек — ставте
  його окремо і свідомо, прочитавши спершу наступний пункт.

## Версія anthropic закріплена на 0.122.* — не змінювати мовчки

Пакет `anthropic` закріплено на гілці 0.122: у версії 1.0.0 з `client.messages.create` прибрано параметр
`temperature`, і курсовий `core/agent.py` — функція `ask()`, якою ходять маршрутизатор, критик і
переписування запиту — падає з `TypeError` на кожному виклику. Курсові файли в цьому репозиторії не
змінюються, тому лагодиться не код, а версія залежності. Модулі 1 і 2 живуть на тій самій гілці 0.122,
тобто закріплення ще й тримає всі середовища на одній версії.

Обмеження навмисно жорстке, щоб конфлікт було видно одразу: пакети фреймворкового стека на кшталт
`langchain-anthropic>=1.5` вимагають `anthropic>=1.0`, і спроба поставити їх поверх цього середовища
впаде на резолвері залежностей із явним повідомленням про конфлікт версій. Це очікувана поведінка, а не
поломка: вона захищає від тихого оновлення, після якого маршрутизатор і критик перестали б працювати.
Рішення про перехід на гілку 1.x — окреме, і воно тягне за собою або зміну курсового `ask()`, або
обгортку замість нього; поки таке рішення не ухвалене, закріплення лишається.

## Сховище фрагментів

Практика шукає або в базі Qdrant, що працює в Docker, або в документах на диску — і вибирає сама. Правило,
команди підняття, поведінка зі згодою на заливання і опис колекцій — у `STORAGE.md`; цей файл однаковий у
всіх модулях, де практика шукає по документах. Коротко:

```bash
docker compose up -d                                  # підняти базу (з кореня репозиторію)
.venv/bin/python -m practice.challenges.qdrant_store --info      # що в ній зараз
.venv/bin/python -m practice.challenges.qdrant_store --migrate   # перенести все, що є
.venv/bin/python -m practice.challenges.suite_download           # $0: 402, 404, 414 і документи довкола 402
.venv/bin/python -m practice.challenges.suite_download --status  # $0: чи не змінилося джерело; нічого не пише
PRACTICE_DOCS=suite .venv/bin/python -m practice.challenges.qdrant_store   # залити набір suite у spec-suite-e5
```

Без бази нічого не ламається: практика падає на документи і щоразу друкує рядок про це разом із командою
підняття.

## Ключ

Секрети живуть у `module4/.env`, звідки їх читає `config.py`:

```
cp .env.example .env    # і впишіть ANTHROPIC_API_KEY
```

Ключ ніколи не потрапляє ні в код, ні в чат, ні в закомічені файли.

## Перша збірка індексів

Перший запуск будь-якої точки входу з векторним пошуком вантажить модель ембедингів
`intfloat/multilingual-e5-small` з Hugging Face (близько 470 МБ, один раз) і рахує вектори фрагментів на
процесорі (десятки секунд). Далі вектори лежать у `practice/index/` і перераховуються лише після зміни
документів. У кожної підмножини документів — тематичної і повної — свій файл кеша, тож прогрів варто
зробити до вимірювань, окремим безкоштовним запуском:

```
.venv/bin/python -m practice.base.smoke --warm    # $0, будує всі індекси
```

## Точки входу і що скільки коштує

Позначка `$0` означає, що прогін не звертається до моделей Anthropic і грошей не коштує.

### Перша картка — агент і мультиагентна система (`practice/base/`, `practice/challenges/`)

```
.venv/bin/python -m practice.base.smoke              # $0: підмножини, схеми, реєстрація, тригери
.venv/bin/python -m practice.base.smoke --warm       # $0: те саме плюс збірка векторних індексів
.venv/bin/python -m practice.base.probe "питання"    # $0: що підніме пошук на це питання, без моделі
.venv/bin/python -m practice.base.system --list      # $0: п'ять запитів виміру і перелік прапорців
.venv/bin/python -m practice.base.system "питання"   # платно: своє питання, мовою питання
.venv/bin/python -m practice.base.system attrs       # платно: один іменований запит через систему
.venv/bin/python -m practice.base.system --confirm   # $0: підтвердити передачу людині
.venv/bin/python -m practice.base.single attrs       # платно: той самий запит через одного агента
.venv/bin/python -m practice.base.compare            # платно: усі п'ять запитів через обох, з вимірами
.venv/bin/python -m practice.challenges.scale        # платно, дешева модель: вимір від обсягу корпусу
.venv/bin/python -m practice.challenges.overlap      # $0: чи допомагає перетин фрагментів пошуку
.venv/bin/python -m practice.challenges.qdrant_store --info     # $0: що зараз у базі
.venv/bin/python -m practice.challenges.spec_download --list    # $0: розділи всієї специфікації
```

Прапорці `system`, `single` і `compare`: `--lexical` — пошук по словах замість ембедингів, `--rewrite` —
переписування бідного запиту дешевою моделлю, `--live` — живий сайт tc39.es для спеціаліста EXOTIC. У `system`
і `compare` ще два, для другої картки: `--fast` — спеціалісти, субагент і критик на дешевій моделі, `--drop
request_handoff` — інструмент прибрано зі списку GENERAL. Що саме шукати у виводі кожної команди — у README,
розділ «Як перевірити імплементацію».

### Друга картка — контекст і пам'ять (`practice/context/`)

Усі платні команди цієї картки йдуть на дешевій моделі каскаду:

```
.venv/bin/python -m practice.context.window              # $0: з чого складається вікно, вартість описів
.venv/bin/python -m practice.context.dialog --list       # $0: сценарії розмови і стратегії історії
.venv/bin/python -m practice.context.memory --info       # $0: що зараз у пам'яті, яка переживає розмову
.venv/bin/python -m practice.context.dialog              # платно: розмова на 18 реплік, повна історія
.venv/bin/python -m practice.context.dialog --history cut       # платно: те саме з обрізанням
.venv/bin/python -m practice.context.dialog --script short      # платно: дві репліки, друга без теми
.venv/bin/python -m practice.context.dialog --chat       # платно: жива бесіда з клавіатури; /кінець — закрити
.venv/bin/python -m practice.context.dialog --chat "Що таке Proxy?"   # платно: перша репліка з рядка, далі з клавіатури
.venv/bin/python -m practice.context.series              # платно: сім прогонів тієї самої розмови, таблиця
.venv/bin/python -m practice.context.drop                # платно: три запити з request_handoff і без, ~$0.4
.venv/bin/python -m practice.context.cleanup --status    # $0: незакриті бесіди — записи, журнали, факти
.venv/bin/python -m practice.context.cleanup --sweep     # $0: прибрати їхній слід
```

Чекбокси, докази і опис виводу кожної з них — у `TASK2-CONTEXT.md`.

Оплачувані прогони за замовчуванням не запускаються нічим, окрім явної команди. Вартість друкується
після кожного прогону; порядок цін видно з `core/cost.py`, а самі числа гуляють між прогонами в
півтора-два рази, бо кількість пошуків обирає модель.

## Змінні оточення

- `PRACTICE_RETRIEVER` — `auto` (типово): база, якщо сервер піднято, інакше документи. Решта значень
  вимикають вибір: `qdrant` — лише база, `vector` — лише документи, `lexical` — пошук по словах.
- `PRACTICE_REWRITE` — `1` вмикає переписування бідного запиту (додатковий виклик дешевої моделі).
- `PRACTICE_EMBED_MODEL` — `e5` (типово) або `bge`: модель ембедингів, кеші в них окремі.
- `PRACTICE_DOCS` — `core` (вісімнадцять розділів навколо `sec-object-type`), `full` (уся специфікація
  ECMA-262: 38 розділів у `practice/docs-full/`, 2436 фрагментів) або `suite` (та сама `docs-full/` плюс
  ECMA-402, 404, 414 і десять вільних документів довкола 402 у `docs-suite/`: 72 документи, 4162
  фрагменти).
- `QDRANT_URL`, `QDRANT_AUTO_INGEST` і решта налаштувань бази — у `STORAGE.md` і в `.env.example`.

## Правила розробки

- Курсові файли не змінюються, `CAPABILITIES` у `domain/backend.py` не розширюється. Практика реєструє
  свої інструменти в `IMPL` через `register()`, який відмовляється працювати при збігу імен із курсовими.
- Живий сайт специфікації вимкнено за замовчуванням: без прапорця `--live` інструмента `fetch_spec`
  немає навіть у списку схем. Дозволений host — лише `tc39.es`, відповіді кешуються на диску.
- Код першої картки нічого не видаляє: кеші, результати прогонів у `practice/out/` і збережені сторінки
  прибирає людина, якщо захоче. Друга картка прибирає слід бесіди — записи `dialog-*.json`, журнали і
  факти про читача в пам'яті — але лише після питання «Бесіду закрито?» або при наступному вході,
  перелічивши незакриті; обговорені теми лишаються. Межі — у `context/cleanup.py`.
