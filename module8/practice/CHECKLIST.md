# Чеклист картки М8 з доказами

Дев'ять чекбоксів списку «Деплой» картки «M8 · Завдання: виведіть свого агента у хмару», у тому ж
порядку, що на дошці. Під кожним — доказ: команда, файл із рядком або цифра з прогону 03.09.2026.
Закрито вісім; єдиний відкритий названий прямо, і біля нього стоїть рівно один крок, якого бракує.

## Деплой — 8 / 9

- [x] **Обрав шлях: serverless / managed runtime / Kubernetes.** Kubernetes, трек C на k3d: хмарного
  акаунта немає, а маніфест пода (`deploy/pod.yaml`) один в один переноситься на EKS чи GKE. Локальні
  прогони треків A (Strands) і B (Google ADK) теж зняті — обидва взяли по два інструменти, — але шлях
  практики саме C.
- [x] **Агент відповідає за HTTP з чужого комп'ютера.** Перевірено 03.09.2026 через тимчасовий
  тунель `cloudflared tunnel --url http://localhost:8081` (адреса виду `https://….trycloudflare.com`):
  з браузера іншого пристрою `/health` віддав `{"ok": true}`, а `curl /ask` з іншої машини на питання
  «Чому NaN !== NaN?» повернув відповідь із розділами 7.2.14 (IsStrictlyEqual) і 6.1.6.1.13
  (Number::equal) — три `search_spec`, guardrail `pass`, 17.8 с, $0.046. Тунель погашено одразу після
  перевірки: публічна адреса витрачає ключ власника.
- [x] **Секрети передаються в runtime, а не зашиті в образ.** Ключ приходить у под через Secret
  `spec-agent-secrets` (`deploy/pod.yaml`, `secretKeyRef`), а Secret випускає `deploy/up.sh` з
  `module8/.env` на кроці 4/6. `practice/Dockerfile` файла `.env` не копіює.
- [x] **Перевірив: без ключа образ падає, а не працює.** `docker run --rm spec-agent-m8:local` пише
  «Не знайдено ANTHROPIC_API_KEY» і завершується з кодом 1 ще на імпорті `config.py` — сервер не
  піднімається. Вивід записаний у README.
- [x] **Поставив ліміт інстансів.** Под рівно один за конструкцією: `replicas: 1` зі стратегією
  `Recreate`, бо PersistentVolumeClaim у режимі ReadWriteOnce другого пода не пустить до диска. Це
  жорсткіша межа, ніж `maxReplicas`: сплеск трафіку не породить нових подів взагалі. Ліміти ресурсів
  на обох контейнерах теж стоять (`deploy/pod.yaml`, `resources.limits`).
- [ ] **Поставив алерт на добову вартість.** Механізм готовий, рішення — за власником акаунта:
  `deploy/up.sh` першим бере ключ `ANTHROPIC_API_KEY_DEPLOY` з `module8/.env`, і зараз там копія
  основного. Крок, якого бракує: створити в консолі Anthropic простір із місячним лімітом $2 і ключем
  у ньому (SETUP.md, крок 5) та замінити значення цього рядка. Після цього стеля зупинить лише сервіс,
  не зачепивши основний ключ.
- [x] **Перезапустив сервіс і подивився, що сталося зі станом.** `kubectl delete pod -l app=spec-agent`
  — деплоймент підняв новий под, у теці `out/` агента лишився тільки вшитий на збірці `mode.json`, а в
  бортовому Qdrant ті самі 4168 точок: стан контейнера вмер, дані на PVC вціліли. Це і є відповідь,
  яку картка просить отримати свідомо.
- [x] **У README є посилання або команда, якою перевірити.** README, розділ «Як запустити»: локальний
  `uvicorn` + `curl /ask`, кластерний `./practice/deploy/up.sh` + `kubectl port-forward` + той самий
  `curl`. Безкоштовні перевірки зібрані в SETUP.md, крок 7.
- [x] **Ключі в .env і секретах хмари, .env у .gitignore.** `module8/.gitignore`, перший рядок — `.env`;
  `git check-ignore module8/.env` це підтверджує. У кластері ключ живе тільки в Secret, в образі його
  немає.
