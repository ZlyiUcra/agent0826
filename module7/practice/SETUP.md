# Установка і прогін

Як підняти оточення практики модуля 7 і як перевірити її безкоштовно. Усі команди виконуються з теки
`module7/`, не з кореня репозиторію: код практики імпортує `practice`, `core` і `config` як пакети верхнього
рівня. Поза модулем практиці не потрібно нічого.

## Оточення

Практика працює в тому самому віртуальному середовищі, що й курсові файли модуля, — `module7/.venv`. Усе, що
вона імпортує, там уже стоїть: `anthropic`, `mcp` 2.1, `qdrant-client`, `python-dotenv`, `pytest` і пакети
OpenTelemetry (`opentelemetry-sdk` 1.44 та експортер OTLP по HTTP). Якщо середовища ще немає, воно ставиться
так само, як у решті модулів:

```
cd module7
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env        # і впишіть ключ
```

Пошук за змістом додатково потребує `fastembed` — його в оточенні немає:

```
.venv/bin/python -m pip install fastembed     # тягне onnxruntime; ~50 МБ коліс, модель ще 128 МБ при першому пошуку
```

Стають `fastembed` 0.8.0 і `onnxruntime` 1.29.0 разом із дрібними залежностями (`pillow`, `loguru`, `mmh3`,
`py-rust-stemmers`, `flatbuffers`).

Це та сама бібліотека, що в практиках модулів 5 і 6: ONNX замість torch. Без неї працює пошук лише по
словах, і всі безкоштовні перевірки проходять — але платний прогін тоді не можна порівнювати з записаними
(див. «Пошук за змістом» нижче).

## Корпус

Агент шукає по найширшому наборі `suite` — той самий корпус специфікації, що в практиках модулів 2-6. Обидві
теки лежать під git разом із практикою: `docs-full/` (уся ECMA-262, 38 файлів) і `docs-suite/` (ECMA-402,
404, 414 і вільні документи довкола 402, 34 файли). Разом 71 документ і 4168 фрагментів; завантажувати
нічого не треба.

Набір задає змінна `PRACTICE_DOCS` (типово `suite`; `full` — лише ECMA-262). Окремо стоїть
`PRACTICE_DEGRADED`: вона підміняє теки на зіпсовану копію `docs-degraded/`, не змінюючи назви набору. Обидві
виставляють самі прогони, руками їх писати не треба.

## Приймач трейсів

Спани йдуть у Arize Phoenix, піднятий локально. Він ставиться **в окреме оточення**, і це не примха: разом із
ним ставляться `mcp` 1.29.1 і `anthropic` 1.3.0, які розійшлися б із версіями модуля й зламали б самого
агента.

```
python3 -m venv ~/.venv-phoenix
~/.venv-phoenix/bin/pip install arize-phoenix
~/.venv-phoenix/bin/phoenix serve
```

Оточення виходить на 946 МБ. Інтерфейс — `http://127.0.0.1:6006`, сервіс у ньому називається `spec-agent`.
Прогін лишає в ньому дерево спанів: корінь звернення, під ним по спану на кожне звернення до моделі й на
кожен виконаний інструмент.

Одну межу варто знати наперед. Змінна `PHOENIX_HOST=127.0.0.1` звужує до локальної адреси лише HTTP-порт
6006; порт gRPC 4317 Phoenix відкриває на всіх інтерфейсах незалежно від неї — адреса зашита в його
`grpc_server.py`. Практика шле спани по HTTP, тож для неї це нічого не змінює, але на спільній машині 4317
лишається відкритим, і закривати його доводиться зовні.

Приймач можна замінити, не чіпаючи практику: `--backend console` друкує спани в термінал і не потребує
нічого, `langfuse`, `langsmith` і `otlp` беруть адреси й ключі з оточення. Перелік адресатів один на модуль —
курсовий `otel_tracing._exporter`.

## Пошук за змістом

Обидва записані прогони знімалися з увімкненим пошуком за змістом, і режим пошуку записується в кожен прогін:
перевірка `test_run_is_comparable` не дасть порівняти прогін по словах із прогоном за змістом. Потрібні
`fastembed` (див. вище) і Qdrant у Docker — той самий контейнер, що в решті практик:

```
.venv/bin/python -m practice.base.setup --status            # $0: що вирішено, що в базі, що змінилося
.venv/bin/python -m practice.base.setup --vectors           # підняти Qdrant і долити лише нове й змінене
.venv/bin/python -m practice.base.setup --verify            # звірити вибірку векторів на підміну
.venv/bin/python -m practice.base.setup --words             # $0: повернутися на пошук по словах
```

Колекція називається `spec7-suite-bge-small` — назва набору документів і ключ моделі векторів. Перше
заливання рахує 4168 векторів і триває близько сорока хвилин на процесорі; грошей воно не коштує, до моделі
Anthropic не звертається. Повторний `--vectors` рахує лише те, що додалося чи змінилося, і на незмінному
корпусі не рахує нічого.

Якщо в тому самому Qdrant уже лежить колекція з цього ж корпусу, порахована тією ж моделлю, — заливати
вдруге не треба. Номер точки будується з ідентифікатора фрагмента через `uuid5` зі сталим простором імен, а
простір і схема ідентифікаторів однакові в практиках цієї лінії, тож наявну колекцію можна просто назвати
новим ім'ям:

```
curl -X POST http://localhost:6333/collections/aliases -H "Content-Type: application/json" \
  -d '{"actions":[{"create_alias":{"collection_name":"<наявна>","alias_name":"spec7-suite-bge-small"}}]}'
```

Після цього `--status` покаже «нових 0, змінених 0» — і це не формальність, а перевірка: він звіряє суму
тексту кожного фрагмента з тією, що лежить у точці. Розійдись корпуси хоч на один фрагмент — він це назве.

Деградований прогін навмисно шукає в ТІЙ САМІЙ колекції: назва набору документів у ньому не змінюється, тож
не змінюється й ім'я колекції. У цьому вся суть досліду — текст оновили, вектори не перерахували.

## Ключ

Ключ Anthropic лежить в одному місці — `module7/.env`, звідки його читає `config.py`. У код нічого не
зашивається. Кореневий `.gitignore` ігнорує `.env*`, тож у репозиторій ключ не потрапляє.

## Безкоштовна перевірка

```
cd module7
.venv/bin/python -m pytest practice -q
```

Тридцять вісім перевірок: форма набору, наявність очікуваних розділів у названих документах, стик між
сервером знань і шаром 2, правила детермінованих перевірок і сам гейт над останнім збереженим прогоном. До
моделі не звертається жодна з них.

Ключ для цього не потрібен, і збережений прогін теж. У щойно клонованому репозиторії, де немає ні `.env`, ні
теки `out/`, `pytest practice` проходить: п'ятнадцять перевірок, решта пропускається з поясненням, що бракує
саме прогону.

Окремо, теж безкоштовно, перевіряється під'єднання агента до сервера знань:

```
.venv/bin/python -m practice.base.agent --tools
```

## Платні прогони

```
cd module7
P=.venv/bin/python

$P -m practice.base.run_traced "How does Object.prototype.toString build the tag?"   # ~$0.05
$P -m practice.base.run_eval --label baseline                                        # ~$1.01, ~10 хв
$P -m practice.base.run_eval --degraded --label degraded                             # ~$1.05, ~10 хв
$P -m practice.base.rejudge --from baseline --label baseline-v2                      # ~$0.04
```

Деградований прогін потребує зібраної копії корпусу; збирає її безкоштовно `python -m practice.base.degrade`,
звіряє — `python -m practice.base.degrade --check`.

`--only same-value,json-valid` звужує прогін до названих кейсів — цим перевіряють зміну в коді, не оплачуючи
всі двадцять. Кожен прогін лишає файл у `out/` і рядок у `data/history.jsonl`.
