## Що доводить ця вправа, а що ні

Доводить рівно те, що написано в її назві: вектори переїхали з матриці в пам'яті процесу в сервер Qdrant,
який працює окремим контейнером, а агент цього не помітив. Не помітив у сильному сенсі — інструмент
`search_docs` повертає йому побайтово той самий `tool_result`, і жоден рядок промпта, точок входу чи
самого агента не змінився.

Не доводить, що базу тут треба ставити. У `README.md`, розділ «Чого ця робота не робить», написано, що
для 283 фрагментів матриця в пам'яті достатня, а Qdrant не додав би нічого, крім залежності. Це лишається
правдою: основним сховищем практики лишається матриця, а Qdrant вмикається окремим прапорцем і лише тоді,
коли сервер піднято. Цінність вправи в іншому — вона показує, що шар пошуку відв'язаний від сховища
настільки, що його можна замінити, не чіпаючи нічого вище. Саме це знадобиться, коли фрагментів стане не
283, а мільйон.

## Як це влаштовано

Сховище — `practice/challenges/qdrant_store.py`, і воно свідомо обходиться без пакета `qdrant-client`.
Клієнт тягне за собою grpcio, protobuf і ще кілька залежностей; замість нього тут чотири запити до
HTTP-API сервера через `urllib` зі стандартної бібліотеки — створити колекцію, залити точки, спитати
розмір, пошукати. Оновлення курсу від 26 серпня 2026 додало `qdrant-client` до курсового
`requirements.txt` — для курсового `knowledge_qdrant.py`; того ж дня пакет поставлено в `module2/.venv`
заради нього одного, практика його не імпортує.

Ім'я колекції збирається з набору документів і моделі ембедингів: `spec-core-e5` для вісімнадцяти
розділів, `spec-full-e5` для всієї специфікації. Обидві частини змінюють вміст, тож в одній колекції їх
косинус означав би різне. Повний опис сховища — у `STORAGE.md`; тут лише те, що вимагає картка.

Точка в колекції — це фрагмент: вектор із 384 чисел плюс увесь текст і паспорт фрагмента (ідентифікатор,
розділ, заголовок, документ, адреса джерела). Тобто Qdrant тримає самодостатню копію того, що потрібно
агентові: і числа для пошуку, і текст для відповіді. Номер точки — місце фрагмента у списку; порядок
документів і поділ на фрагменти сталі, тож повторне заливання лягає на ті самі номери.

Заливання не рахує вектори заново — бере їх із кеша `practice/index/*.npy`, який уже порахований
звичайними прогонами. Тому воно триває секунди й навіть не піднімає модель ембедингів:

```
── Заливання фрагментів у Qdrant http://localhost:6333 ──
  фрагментів:   283, вектор 384 чисел, з кеша
  колекція:     spec-core-e5 — створена
  залито:       283 з 283
  у колекції:   283 точок

real    0m2.317s
```

Нічого не видаляється: колекція створюється, лише якщо її немає, точки пишуться поверх своїх номерів, а
якщо в колекції виявиться більше точок, ніж фрагментів у документах, скрипт скаже про це вголос і лишить
рішення людині. Розбіжність довжини вектора теж не «виправляється» мовчки — стара колекція лишається на
місці з поясненням, що з нею робити.

## Команди

Усі — з теки `module2/`, інтерпретатором `.venv/bin/python`. Повний перелік і опис поведінки сховища —
у `STORAGE.md`, спільному для всіх модулів.

```bash
docker compose up -d                                     # підняти сервер (з кореня репозиторію)
python -m practice.challenges.qdrant_store --up          # те саме, але з теки модуля
python -m practice.challenges.qdrant_store               # залити фрагменти, $0, секунди
python -m practice.challenges.qdrant_store --migrate     # перенести все: обидва набори і документацію
python -m practice.challenges.qdrant_store --info        # що зараз у колекції, $0
python -m practice.challenges.qdrant_store --check       # звірити видачу з матрицею .npy, $0
PRACTICE_RETRIEVER=qdrant python -m practice.base.compare  # безкоштовний прогін на Qdrant
python -m practice.base.ask replace --qdrant             # агент на Qdrant, платно
python -m practice.challenges.kb_qdrant                  # курсові правила в сервер, $0
python -m practice.challenges.kb_qdrant --check          # правила: пам'ять проти сервера, $0
python -m practice.challenges.ragas_modes                # метрики Ragas у двох режимах, платно
```

Що друкує кожна з них — `README.md`, підрозділи «Метрики Ragas» і «Що друкує кожна команда»;
поведінка сховища і опис колекцій — `STORAGE.md`.

Дашборд — http://localhost:6333/dashboard. Адреса сервера береться зі змінної `QDRANT_URL`, типово
`http://localhost:6333`.

Зупинити сервер, не втрачаючи даних: `docker stop agent0826-qdrant`. Дані лежать у томі
`agent0826-qdrant` і переживають зупинку, перезапуск і видалення контейнера; зникають вони лише разом із
самим томом, тобто за явною командою `docker volume rm agent0826-qdrant`.
